**Minor release (0.34 → 0.35).** tagave knows whether it can reach each music folder. The banner says since when a folder is offline, and a dead share can no longer freeze the file worker. Repair runs one at a time.

## Before you update

- **Going back to 0.34 means a restore.** This update changes the database (migration 0097). The updater takes a backup first and restores it on its own if the update fails; to return to 0.34 later, follow [Going back](https://github.com/xooxoxxo/tagave/blob/v0.35.0/docs/operations.md).

## New

- **Each music folder has a status:** online, offline or not connected. tagave checks every 30 seconds. It asks the share's server first and never touches the folder while the server is silent; otherwise it checks the folder in a helper it gives up on after 15 seconds, so a dead share can never freeze the file worker. Two bad checks in a row mark a folder offline, one good check brings it back, and a quick scan follows. ([cbf30ee](https://github.com/xooxoxxo/tagave/commit/cbf30ee), [38ef08c](https://github.com/xooxoxxo/tagave/commit/38ef08c), [0ca9ec8](https://github.com/xooxoxxo/tagave/commit/0ca9ec8), [578f3df](https://github.com/xooxoxxo/tagave/commit/578f3df), [742e846](https://github.com/xooxoxxo/tagave/commit/742e846))
- **The banner says since when:** "Music folder offline since 14:02", "Music folder not connected since 14:02", or "2 music folders offline", with the way to Music folders. It still shows to the owner only. ([9d89b31](https://github.com/xooxoxxo/tagave/commit/9d89b31), [0741c2f](https://github.com/xooxoxxo/tagave/commit/0741c2f), [ecf049d](https://github.com/xooxoxxo/tagave/commit/ecf049d))

## Fixed

- **The music self-heal acts only when the share's files are really gone.** A renamed folder, a new empty folder or an unreadable mount list no longer restarts parts. A heal rescans only the folders it was about. ([b266e37](https://github.com/xooxoxxo/tagave/commit/b266e37), [a96f238](https://github.com/xooxoxxo/tagave/commit/a96f238), [84f8675](https://github.com/xooxoxxo/tagave/commit/84f8675), [e37007b](https://github.com/xooxoxxo/tagave/commit/e37007b))
- **Folder checks never pile up:** a stuck check is never joined by a second one, an error the rules don't name reads offline, and a status change is kept until it is saved. ([343026e](https://github.com/xooxoxxo/tagave/commit/343026e), [68b5fae](https://github.com/xooxoxxo/tagave/commit/68b5fae), [53ae566](https://github.com/xooxoxxo/tagave/commit/53ae566), [c929dd0](https://github.com/xooxoxxo/tagave/commit/c929dd0))
- **One repair at a time:** the Repair button, the installer's repair and the music self-heal never run at once. A second one is told a repair is running. ([f18e224](https://github.com/xooxoxxo/tagave/commit/f18e224), [7355661](https://github.com/xooxoxxo/tagave/commit/7355661))
- **Ctrl-C on the installer's repair** still records the repair in the audit log, and the repair stops moving parts at once. ([f18e224](https://github.com/xooxoxxo/tagave/commit/f18e224), [7355661](https://github.com/xooxoxxo/tagave/commit/7355661))

## For self-hosters

- **A failed repair in the terminal** now says "Run the installer again with --repair". ([f18e224](https://github.com/xooxoxxo/tagave/commit/f18e224))
- **`GET /system/music-folder`** returns a list of folders with status, since and reason. It keeps `paths` for one more release. ([9d89b31](https://github.com/xooxoxxo/tagave/commit/9d89b31))
- **Migrations:** 0097 music folder status, and a parked jobs table that stays empty until a later release.
- The installer test runs about twice as fast. ([a228138](https://github.com/xooxoxxo/tagave/commit/a228138))
