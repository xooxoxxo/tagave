**Minor release (0.37 → 0.38).** On Linux, a writable install can now start every part while the NAS is off, and picks the music share up when it comes back, without a restart. Every other install keeps its music folder mounted as before.

## Before you update

- Nothing to do before this update. An existing install keeps its music folder mounted exactly as today, even when an older updater or an older copy of the installer runs the update.

## New

- **Every part starts with the NAS off (writable installs on Linux).** When the music folder is a network share under `/mnt`, `/media` or `/srv`, the installer can mount the folder above it instead. A share that is off at start no longer stops the file worker or the player, and when it comes back it shows up in the running parts. The installer lists what else that folder holds and asks first. ([cb2e324](https://github.com/xooxoxxo/tagave/commit/cb2e324), [a17aa71](https://github.com/xooxoxxo/tagave/commit/a17aa71), [4586100](https://github.com/xooxoxxo/tagave/commit/4586100))
- **Read-only installs keep the direct mount.** A share that reconnects while tagave runs would arrive writable in the new layout, so a read-only music folder stays mounted directly and stays read-only. The installer says so in one line. Rootless Docker, snap Docker and Docker Desktop keep the direct mount too. ([86a466d](https://github.com/xooxoxxo/tagave/commit/86a466d))
- **The music self-heal leaves the parts running** in the new layout: it mounts the share and restarts nothing. ([65a6d60](https://github.com/xooxoxxo/tagave/commit/65a6d60), [ecd70e3](https://github.com/xooxoxxo/tagave/commit/ecd70e3))

## Fixed

- **An update never changes how the music folder is mounted.** The mount's read-only or writable mode still comes from `TAGAVE_MUSIC_MODE`, so every earlier `.env` keeps its mount. ([18b2ff8](https://github.com/xooxoxxo/tagave/commit/18b2ff8), [e7d4838](https://github.com/xooxoxxo/tagave/commit/e7d4838))
- **The worker leaves `/mnt/music` alone** when it cannot read the mount table. ([e502a8a](https://github.com/xooxoxxo/tagave/commit/e502a8a))

## For self-hosters

- **Installer flags:** `--music-parent DIR` names the folder above the music share; `--music-direct` keeps the direct mount and is remembered until a run with `--music-parent`. ([cb2e324](https://github.com/xooxoxxo/tagave/commit/cb2e324), [86a466d](https://github.com/xooxoxxo/tagave/commit/86a466d))
- **fstab advice:** a music share line without `nofail` (or without `_netdev` for NFS and SMB) gets a suggested line once. tagave never edits fstab. ([cb2e324](https://github.com/xooxoxxo/tagave/commit/cb2e324))
- **New `.env` settings**, written by the installer only for the new layout: `TAGAVE_MUSIC_BIND_SOURCE`, `TAGAVE_MUSIC_BIND_TARGET`, `TAGAVE_MUSIC_NAME`, `TAGAVE_MUSIC_PROPAGATION`, `TAGAVE_PLAYER_BIND_TARGET`, `TAGAVE_PLAYER_MUSIC_FOLDER`. The player never purges missing songs.
- **The bare-metal worker unit** no longer requires the music mount at start.
- **Docs:** install.md (the two layouts, the flags, the recommended fstab line), operations.md (a share that goes offline) and security.md (what the folder above the share exposes). ([33ff507](https://github.com/xooxoxxo/tagave/commit/33ff507))
- **CI** tests the layout on a real NFS share with the NAS cut off. ([3e5a8c7](https://github.com/xooxoxxo/tagave/commit/3e5a8c7))
- No migration and no new dependencies. The Coolify, Dokploy, Unraid and Portainer templates keep the direct mount.
