**Minor release (0.38 → 0.39).** Existing writable installs on Linux move to the music share layout from 0.38 on their own, so every part starts while the NAS is off. Settings › Status warns when the music share may stop the computer starting, and Repair calls an offline folder with every part running healthy.

## Before you update

- Nothing to do before this update. Shortly after the update finishes, tagave checks whether this install can use the new layout and moves it if every check passes. Read-only installs, rootless Docker, snap Docker and Docker Desktop stay as they are.

## New

- **Existing installs move on their own.** A writable install whose music folder is a network share under `/mnt`, `/media` or `/srv` moves to the layout new installs got in 0.38, when every check the installer makes passes and everything else next to the share is a mount point. Only the file worker and the player restart. A refusal changes nothing and logs one line why. Repair, the update and `install-tagave.sh update` check again each time, so an install that becomes eligible later still moves. ([5a8319fb](https://github.com/xooxoxxo/tagave/commit/5a8319fb), [eca0c607](https://github.com/xooxoxxo/tagave/commit/eca0c607), [bbff364a](https://github.com/xooxoxxo/tagave/commit/bbff364a), [8d6e0910](https://github.com/xooxoxxo/tagave/commit/8d6e0910), [3ca2a6f4](https://github.com/xooxoxxo/tagave/commit/3ca2a6f4))
- **Player data stays.** The player's music folder changes, but songs keep their ids, so stars, playlists and tagave's track map stay as they were.
- **Settings › Status: "Music share at boot".** When the music share's fstab line has no `nofail`, the row says it "may stop this computer starting while the NAS is off", with the suggested line behind "?". A soft mount gets a "Music share mount: Mounted soft" note. ([40a0818f](https://github.com/xooxoxxo/tagave/commit/40a0818f), [c2e82389](https://github.com/xooxoxxo/tagave/commit/c2e82389), [6019a3ee](https://github.com/xooxoxxo/tagave/commit/6019a3ee))
- **Repair with the NAS off.** In the new layout, an offline music folder with every part running ends "All 5 parts running. The music folder is offline: its work waits and starts again when it's back." Repair no longer waits for the share. ([6eb95183](https://github.com/xooxoxxo/tagave/commit/6eb95183), [cb7529d6](https://github.com/xooxoxxo/tagave/commit/cb7529d6))

## Fixed

- **An update that cannot use the new layout keys** checks again without them, so it never fails over the move. ([3002e3b5](https://github.com/xooxoxxo/tagave/commit/3002e3b5))
- **The move never runs during a Repair or another update.** ([22754e01](https://github.com/xooxoxxo/tagave/commit/22754e01))

## For self-hosters

- **`cli.js music-layout`** shows what the move would do; `--apply` does it. To stay on the direct mount for good, set `TAGAVE_MUSIC_LAYOUT=direct` (the installer's `--music-direct` does this). How to undo a move is in docs/operations.md. ([22754e01](https://github.com/xooxoxxo/tagave/commit/22754e01), [18105dfe](https://github.com/xooxoxxo/tagave/commit/18105dfe))
- **The host checks** read the mount table, `/etc/fstab`, the parent folder's propagation and its names through fixed read-only commands. They never touch the music folder itself. ([5a8319fb](https://github.com/xooxoxxo/tagave/commit/5a8319fb), [22983985](https://github.com/xooxoxxo/tagave/commit/22983985))
- An install updated with an older local `install-tagave.sh` moves at the next Repair or update.
- No migration and no new dependencies.
